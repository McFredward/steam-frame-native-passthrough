# Private pairing and real reverse-control runtime (2026-10-18)

This increment connects the existing authenticated sender/receiver adapter ports to actual private pairing files, OS randomness, and nonblocking TCP. It is a library with explicit cold preparation, not an installed/autostarted companion. It does not change a Steam process, video pixels, shaders, renderer, decoder, startup configuration, or installability manifest.

## Actual integration ports

A worker owns `ControlRuntime` and its lifetime. `prepare(ControlRequest)` defaults off and returns before file, random, or socket work unless explicitly requested. The producer loads its selected private key, generates a fresh binding and local nonce, and listens on an explicitly supplied numeric loopback/RFC1918 IPv4 address. The receiver loads its own selected key, generates its nonce, and connects to that explicit endpoint. No DNS, public/ANY bind, scanning, environment mutation, reconnect timer, or automatic restart is provided.

The caller must stop/join all callback users before preparing a new session or destroying the runtime. The encoder sealer uses a try-lock: contention refuses metadata append rather than waiting behind cold file or worker I/O. Receiver parsing/verifying and `tick()` belong on a worker, not the compositor rendering thread. The fixed four-entry control and receipt rings apply backpressure; a tick makes at most eight nonblocking send and eight receive attempts. Each packet is exactly the existing 176-byte HMAC envelope, and partial TCP reads never become messages.

Use these existing production adapter ports:

1. Producer: obtain `localConfig(config, localAuthority)` and call `SenderAdapter::request(config, localAuthority.channel, actualVerifiedSource, runtime.senderSealer())`. Local signing authority is not a received peer confirmation. Source identity, codec generation, and actual complete-AU provenance remain the real provider's responsibility.
2. Receiver: `configuredLocal(config)` supplies configuration only, without fabricated channel trust. Call `Receiver::beginAuthenticated(authority, config, runtime.receiverVerifier(), runtime.verifierContext())`. The authority must come from the admitted actual video lifecycle. The first actual authenticated producer HELLO in that video establishes the binding exactly once. Every later video envelope is checked against that same source session/generation and authenticated independently.
3. Keep all producer HELLO/ACK/COMMIT/probe packets on the existing ordered SEI/video route. For each receiver action, encode its 80-byte body and call `queueControl`. Only call `Receiver::markOutboundSent` when the matching ticket appears in `pollSent`, after all 176 bytes were accepted by `send()`. This is a local socket handoff receipt, not proof of remote receipt. Consuming the peer's authenticated ACK/COMMIT supplies the latter protocol evidence.
4. Producer `pollVerified` returns only MAC-verified 80-byte bodies and channel evidence. Pass these to the existing `SenderAdapter::receiveControl` or probe consumer. `TransportConnected` means only TCP connectivity; `peerVerified()` means successful envelope authentication, not complete compatible mutual handshake or image permission.
5. On `Lost`, `AuthenticationRefused`, stop/reconfigure, or source generation change, reset the adapter/handshake as well as this runtime. Invalid complete TCP packets or EOF revoke the runtime key/session and clear queued outputs immediately. Missing peers leave ordinary video unchanged.

Producer control is intentionally not also sent over TCP. The auth protocol has one monotonic sequence in each direction; dividing the producer direction between independently delayed TCP and video would reject valid late video as replay. Receiver-to-producer control uses TCP; producer-to-receiver control and the exact coded-AU probe use video. There is no secret in SEI, argv, status strings, logs, or manifests.

## Selected private credentials

The loader reads exactly `pairings/active.json`, then that selected ID's JSON. It never tries retained keys. This matches the setup transaction's `sfnp-active-pairing-v1` and `sfnp-pairing-v1` schemas. Duplicate/unknown fields, escaped/path-valued IDs, noncanonical hex, role/version mismatch, broad permissions, links, oversize files and changed selection refuse transactionally. The selected file identity and contents are reread before publishing any key.

Linux walks physical directory components with `openat(O_DIRECTORY|O_NOFOLLOW)`, pins the final directory FD, requires its owner and private access, and opens only 0600 regular single-link same-owner files beneath it. Windows holds non-reparse directory handles for every path component, opens final non-reparse single-link files, and requires the installer-owned current-user owner plus exact protected SYSTEM/OWNER RIGHTS ACL. Files are read through the checked handle. Windows ACL/ancestor behavior has been cross-compiled, not validated on an actual Windows machine in this checkpoint. Intermediate directory ownership is not uniformly required (system roots and `/tmp` may be owned by the OS); the walk prevents redirection, and the platform-specific final directory/file checks enforce local privacy. Keys and read buffers are erased on scope exit/reset; caller-owned successful outputs must also be erased after preparation.

## Focused evidence and limits

The new Linux fixture uses real 0700/0600 files and real loopback sockets through the actual existing `AuthSession`, `SenderAdapter`, Annex-B SEI parser and `Receiver`. It completes authenticated HELLO/ACK/COMMIT without replacing original VCL bytes, checks partial reads, bounded queues, wrong/private credentials, source-bootstrap ordering and EOF revocation. A test-only libc read interposition replaces `active.json` with an identical-content different-inode file during the actual credential read; publication must refuse. No production timing/test callback is present.

This does **not** yet wire installed helper ownership or a worker event loop into the version-pinned PC/Frame providers. The current receiver coded-buffer provider still marks complete-access-unit proof false; this runtime deliberately refuses to turn that into an authenticated-video assertion. The connection/generation authority must be sourced there, not made up from a socket or counter. Exact decoder-output/selected-resource binding and genuine full-resolution RGB/coverage mapping remain necessary separate work. Even a real loopback mutually confirmed handshake leaves `coveragePermitted()` false. This is neither a headset quality fix nor hardware proof of a functioning new full-resolution route.

Validation for this checkpoint: 202 focused actual-file/loopback checks pass in the normal and ASan/UBSan builds; the new CMake target and single CTest pass. Four semantic controls are rejected independently (broad file mode, replaced selection identity, ignored invalid MAC, retained trust after EOF). Actual production-module Win64 and AArch64 shared cross-links pass. These are software results, not installed-device or headset evidence.
